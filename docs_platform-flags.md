# Платформенные флаги и перехват: winws2 (Windows) vs nfqws2 (Linux)

Источник: wiki.zapret.moe — «Что такое Zapret 2 (nfqws2)?» (раздел «на Windows
и на Linux — одна программа под разными именами»), сверено с документацией
автора (docs/manual.md репозитория zapret2) в октябре 2026.

## Одна программа, разные имена

| Имя файла | Система | Откуда название |
|---|---|---|
| `winws2` | Windows | `win` — Windows |
| `nfqws2` | Linux, OpenWrt, Android (root) | `nfq` — NFQUEUE, механизм Linux |
| `dvtws2` | FreeBSD/OpenBSD | `dvt` — divert (BSD) |

На macOS Zapret 2 не работает (нет средства перехвата пакетов).

## Что одинаково (переносится между системами без правок)

Вся часть «как обмануть DPI»: Lua-скрипты, профили, фильтры профиля
(порты, hostlist/ipset), `--payload`, `--out-range`, блобы, вызовы
`--lua-desync`. Строка вида `--filter-tcp=443 --lua-desync=fake:…`
одинакова на обеих системах.

Оговорка: одинаковая запись ≠ одинаковый результат. Обманка `ts` опирается
на TCP timestamps: на Linux они обычно включены, на Windows по умолчанию
выключены — стратегия с `ts` ведёт себя по-разному.

## Что отличается (слой перехвата — платформенный)

| | Windows (`winws2`) | Linux (`nfqws2`) |
|---|---|---|
| Кто перехватывает пакеты | Драйвер WinDivert, встроен в `winws2` | `nftables`/`iptables` → очередь NFQUEUE → `nfqws2` |
| Как указать, какой трафик ловить | Флаги `--wf-*` в командной строке | Правила nftables/iptables; программе — номер очереди |
| Флаги, которых нет на другой системе | `--wf-*`, `--ssid-filter`, `--nlm-filter` | `--qnum`, `--fwmark`, `--bind-fix4`, `--filter-ssid` |
| Чей трафик обрабатывается | Только компьютер, где запущен `winws2` | И свой, и проходящий (на роутере — вся домашняя сеть) |

## Следствия для переноса (PrimeProxy)

1. **Пресет нельзя вставить целиком в Linux**: первые строки пресета —
   флаги `--wf-*`, которых в сборке для Linux нет. Переносима часть с
   профилями и стратегиями. В обратную сторону: команда запуска с Linux
   содержит `--qnum`/`--fwmark`, которых нет в `winws2`.
2. В крейте `primecore-ws` перехват уже отделён: работа с пакетами и
   процессами идёт через трейты (`ProcessSpawner`/`SpawnedProcess`,
   `SystemProbes`), модуль `windivert.rs` держит только диагностику
   ошибок WinDivert — это Windows-слой.
3. Будущий Linux-срез запуска должен: генерировать правила
   nftables/iptables (нужен `primecore-privilege` — уже есть), выбирать
   номер очереди (`--qnum`), выставлять `--fwmark`/`--bind-fix4` по
   надобности, и НЕ подставлять в команду `--wf-*`.
4. Python-эталон (zapretgui) содержит только Windows-ветку: для
   Linux-флагов parity-тестов против python не будет — значения берутся
   из документации zapret2 (docs/manual.md) и сверяются с ней.
