# PrimeBypass: спецификация переделки интерфейса

Дата: 2026-11-06. Основание: пользовательский план и согласованный визуальный эталон https://vpn.sphereprime.ru/.

## Цель и границы

Полностью заменить компоновку оболочки `next/app-shell`, сохранив действующие API Rust-ядра, системные операции и семантику выбора профилей. Целевые платформы: Electron Windows/Linux и общая Vite-сборка для Android. Не изменять `crates/`, HTTP-контракты, механизм повышения прав и Electron bridge ради редизайна.

В рабочем дереве уже присутствуют изменения шрифтов, HTML, package.json/lock, TitleBar, main.tsx и стилей, а также новые Backdrop и PrimeMark. Сохранить и учесть их; не сбрасывать и не включать посторонние изменения в коммиты. Индекс также содержит ранее подготовленные удаления шрифтов: не коммитить весь индекс без разделения авторства изменений.

## Визуальная система

Использовать подтверждённые токены сайта: фон #101010, приподнятый фон #141414, панели #171717, hover #1d1d1d, акцент #ff6a35, основной текст #f1efe9, вторичный #8d8a84. Границы белые с прозрачностью 0.07, усиленные 0.14. Inter для интерфейса, JetBrains Mono для технических подписей. Скругления 12–26px, мягкое оранжевое свечение.

Фон: медленно движущаяся сетка, рассеянное оранжевое свечение и подсветка за курсором. Декорации не перехватывают ввод. При prefers-reduced-motion отключать движение, пульсацию и бегущие кольца, сохраняя статическое обозначение состояния. На touch подсветка курсора не требуется.

Удалить бегущие строки, огромные контурные номера, повторные CTA, счётчики-декорации и номера вида 02 / 02 на карточках.

## Оболочка и навигация

Вместо sidebar — шапка 56px. Слева существующий PrimeMark (три наклонных столбика) и PrimeBypass. В центре таблетки с иконкой и подписью: Обход, Разблокировка, Проверка, Анализ лога, DNS, Telegram. Активная таблетка светлая с тёмным текстом. Справа общий индикатор состояния и существующие кнопки окна через текущий Electron bridge.

Индикатор различает проверку связи, включённый/выключенный обход и недоступное ядро. «Выключен» нельзя выводить только из ошибки запроса. Статус получать из существующих health и ws/status; по нажатию открывать Обход. Опрос должен работать на любой вкладке, очищаться при размонтировании и не создавать параллельных владельцев одного журнала.

На промежуточной ширине скрывать подписи навигации, сохраняя aria-label и title. На телефоне навигация внизу с учётом safe-area; шапка остаётся компактной. Стартовые пороги для проверки: desktop от 1200px, иконки 768–1199px, нижняя навигация до 767px. Если содержимое не помещается, порог уточнить по фактическому измерению, не допуская горизонтального скролла всей страницы.

## Общие компоненты и стили

Каждый компонент в отдельном файле `src/components/ui/`: Panel, PageHead, PowerButton, Segmented, Notice, Switch, Stat, EmptyState. Использовать семантические button/input, доступные подписи, видимый keyboard focus. Switch имеет роль switch и aria-checked; Segmented отражает выбранный вариант. PowerButton поддерживает disabled, pending, on и off без повторной отправки операции.

PageHead: маленькая моно-подпись с оранжевым квадратом, жирный заголовок 40px на desktop, строка описания, справа действия. На телефоне заголовок уменьшается и действия переносятся.

Основная сетка страниц: гибкая левая колонка и правая около 380px, sticky ниже шапки. На узком экране — одна колонка в осмысленном порядке. Sticky не должен делать содержимое длинной панели недоступным.

Структура CSS: tokens.css, base.css, components.css, shell.css, pages/*.css; styles.css только собирает импорты. Удалить старые bypass.css, hosts.css, telegram.css и _legacy-reference после переноса всех потребителей. Общие классы не должны зависеть от частных стилей другой страницы.

## Обход

Большой главный блок с круглой кнопкой питания около 170px. Выключено — серое; запуск — оранжевое вращающееся кольцо; работает — оранжевый фон, свечение и расходящиеся кольца. Рядом состояние, пояснение, чипы движка, PID, профиля и прав. Справа автоподбор и флаг «сразу запустить».

Ниже слева профили: Все сайты | Точечные, поиск. Все сайты — универсальные пресеты. Точечные — компактные плитки сервисов по категориям, значок, название, switch; раскрываемый выбор пресета занимает ширину группы. Не смешивать режимы при запуске. Сохранить localStorage-ключи, выбор пресетов, fallback старого ядра без универсальных целей и поведение автоподбора.

Справа параметры запуска (режим списков, qnum, команда) и высокий терминал журнала. Сохранять правила платформы, инкрементальный журнал, ограничение памяти и прокрутку только если пользователь у нижней границы.

Вынести управление состоянием, polling, права, старт/стоп и автоподбор из BypassPage в `src/hooks/useBypass.ts`. Разделить визуальные блоки в `src/components/bypass/`. Владелец состояния должен быть явным; общая шапка не запускает повторный автоподбор и не сбрасывает выбор.

## Разблокировка (hosts)

Слева поиск, выбрать всё/очистить, категории сервисов. Плитка переключает выбор целиком; отдельное раскрытие доменов не меняет выбор, вложенных button внутри button нет. Каталог перенести без потери данных в `src/data/hostsServices.ts`.

Справа sticky «Изменения»: путь hosts, существующие записи, +добавится и −уйдёт, применение с явным inline-подтверждением, строки управляемого блока под спойлером. После изменения выбора сбрасывать устаревшее подтверждение/предпросмотр. Существующие правила управляемого блока и API предпросмотра/применения не менять.

## Проверка

Слева группы доменов с chips и выбрать/снять для каждой группы. Справа действие проверки, прогресс X из Y, доступно/заблокировано/медленно, результаты с цветовой меткой, текстовым статусом и миллисекундами.

При наличии заблокированных — «Включить профили для заблокированных»: передать соответствующие цели в Обход и показать результат применения выбора. Не запускать движок автоматически этим переходом. Соответствие доменов сервисам брать из текущих данных/правил профилей, неизвестные домены не включают произвольный профиль.

## Анализ лога

Слева Segmented Файл | Текст, путь к файлу или textarea. Справа существующая сводка: счётчики, профили, хостлисты. Ниже таблица соединений на всю ширину; на телефоне её собственный горизонтальный скролл, а не скролл страницы. Сохранить действующий контракт анализа и состояния ошибок.

## DNS

Три подвкладки вместо длинной страницы:
- Обзор: текущие системные DNS и DoH, проба запроса и установка DNS.
- Сверка серверов: домен, проверка на всех серверах, вердикт и результаты.
- Каталог: существующие фильтры и плитки провайдеров.

Сохранить все существующие поля запросов и системные операции; переключение подвкладок не должно терять введённые значения или завершённый результат без необходимости.

Ниже слева порт, фронт и код воркера; справа схема туннеля из четырёх шагов, отражающая существующий механизм, без новых серверных возможностей.

## Состояния и совместимость

Все страницы имеют loading, пустые данные, недоступное ядро, ошибку операции и успешный результат. Не выдавать техническую ошибку за успешное выключение. Блокировать повторные опасные действия во время запроса. Размонтирование не должно оставлять таймеры или обновлять несуществующий UI.

Проверять длинные названия пресетов, домены, команды, пути и логи. Технические блоки ограничиваются контейнером. Не добавлять зависимости без необходимости. Существующие API и ключи хранения сохраняются.

## Проверка и сдача

Поэтапные изменения: оболочка/общие компоненты → обход → hosts/проверка/логи/DNS/Telegram. Перед кодом каждого этапа определить воспроизводимый тест или проверку регрессии; после — TypeScript check и Vite build. Сейчас package.json содержит build, но отдельного test script нет; не объявлять существование автоматических тестов до их обнаружения/добавления.

С работающим ядром проверить: старт/стоп обхода, автоподбор с обоими значениями сразу запустить, права/отказ, hosts предпросмотр и подтверждение применения, проверку доменов и переход к профилям, DNS пробу/сверку/каталог, Telegram старт/стоп/ссылку/воркер, оба источника анализа лога. Системные изменения выполнять осознанно, фиксируя исходное состояние и восстанавливая его после проверки; не маскировать ограничения прав моками.

Снимки всех шести страниц desktop и phone, а также трёх DNS-подвкладок. Минимальные ширины проверки: 1440, 1024 и 390px; дополнительно 320px на отсутствие overflow. Проверить клавиатуру, focus, reduced motion, недоступное ядро и browser console.

В CHATS.md записать фактические изменения, выполненные команды, UI-сценарии и оставшиеся ограничения. Коммиты делать по функционалу, включая только собственные изменения; не push без отдельного запроса. Успех каждого сценария подтверждать результатами, а не ранее сообщённой проверкой GET-маршрутов.
